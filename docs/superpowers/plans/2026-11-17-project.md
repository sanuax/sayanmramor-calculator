# Проект из нескольких изделий -- Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Клиент собирает в калькуляторе несколько изделий (проект): все стоят в одной 3D-сцене, у
проекта одна цена (общий раскрой по камням), один итог, одна заявка, одна ссылка и один паспорт.

**Architecture:** Форма остаётся редактором одного, активного изделия. Проект -- список снимков
изделий (`{ productKey, stoneId, fields }`, `fields` -- как у ссылки-паспорта). Неактивные изделия
считаются чистыми модулями через «поддельный doc» из снимка. Новые чистые модули: `project-model.js`
(данные, ссылка pv=2, хранение), `project-pricing.js` (цена изделия, общий раскрой, итог),
`visualizer/project-layout.js` (витрина: сдвиги изделий). ThreeScene рисует активное изделие, как
сейчас, плюс «соседей» со сдвигами относительно него.

**Tech Stack:** ванильный JS (UMD-модули, `node --test`), three.js (ES module `visualizer/three-scene.js`),
одна страница `sayanmramor-calculator.html`.

**Spec:** `docs/superpowers/specs/2026-11-17-project-design.md`

## Global Constraints

- Только локально: ничего не пушить и не выкладывать (`deploy_regru.sh` не запускать) без слова владельца.
- Пока в проекте одно изделие, страница выглядит и считает ровно как сейчас (+ кнопка «+ Добавить изделие»).
- Старые ссылки-паспорта (pv=1) открываются как раньше, одним изделием.
- `data/slabs.json` руками не трогать. Не форс-пушить `rate-catalog-subcategories`.
- После правки любого JS -- `node scripts/stamp_assets.js`; новые скрипты подключать в странице так же
  (`?v=` штамп), иначе тест `asset-stamps` упадёт.
- Тексты для клиента -- по-русски; комментарии в коде -- как в соседнем коде (английский, с датой
  и «the owner»).
- Тесты гонять на LF-копии (как CI): 5 тестов, сверяющих разметку регулярками, падают на CRLF-копии.

## Review Focus

1. Переключение изделий: выбор одного не протекает в другое (раковина, кромка, бортик, форма Г/П,
   подступенки, вид фасада/камина) -- тест: снимок A → сброс → снимок B → снимок A == исходному A
   (Task 5, проверка в браузере по сценарию).
2. Два изделия одного камня, которые по отдельности помещаются, а вместе нет в наличии (insufficient
   stock) -- итог «уточнит менеджер» с понятной причиной, а не падение (Task 2, тест).
3. Изделие без цены (камень распродан, размер вне лимита, нет ставки) в середине проекта -- остальные
   показывают цены, итог «уточнит менеджер» (Task 2, тест).
4. Новое изделие ещё без типа/размеров -- в 3D только соседи, без «призрака» прежнего активного
   (Task 4/5, проверка в браузере).
5. Удаление активного изделия и изделия перед активным -- активным становится соседнее, индексы и
   сдвиги в 3D верные (Task 1 тест, Task 5 браузер).

### Task 2: `project-pricing.js` -- цена изделия и проекта

**Files:**
- Create: `project-pricing.js`
- Test: `tests/project-pricing.test.js`

**Interfaces:**
- Consumes: `ConstructorState.buildPricingInputs(state, { catalog, edgeLengthM })`, `Pricing.calculatePrice(params)`, `Pricing.planMaterial({ slabs, job, marginCm, usageLimit })`, `Pricing.planSurface(slabs, areaM2, usageLimit)`, `EdgeLength.openEdgeLengthM(layout)`, `GeometryModel`, `SceneLayout`, `ProductTypes.{ PRODUCTS, SAW_MARGIN_CM, SLAB_USAGE_LIMIT }`, `RateCatalog`.
- Produces (global `ProjectPricing`):
  - `edgeLengthOf(state) -> number` (как `openEdgeLengthM` в странице: 0 без кромки)
  - `priceItem(state) -> { kind: 'incomplete'|'manual'|'ok', reason?, result?, inputs?, edgeLengthM }` -- тот же вызов `calculatePrice`, что делает страница (`computeAndRenderSummary`), с опциями из `state.options`; `incomplete` -- нет продукта/размеров/камня или `job.missing`; `manual` -- камень недоступен или `!result.ok`.
  - `priceProject(states: state[]) -> { kind, total, measure, delivery, minOrderTopUp, items: [{ kind, price, stoneShare, work, reason? }], groups: [{ stoneId, nSlabs, subtotal, itemIndexes }], reason? }`
    - камень: изделия с `kind 'ok'` группируются по `state.stone.id`; детали (`job.pieces`) всех изделий группы -- один `planMaterial`; «площадные» (`job.surfaceAreaM2`) -- `planSurface` на плитах, не взятых деталями; стоимость группы = сумма; доля изделия = стоимость группы × площадь изделия / площадь группы.
    - работа изделия = `result.work - result.measure - result.delivery`; `null`, если `result.work === null`.
    - замер/доставка: один раз -- если хотя бы у одного изделия `state.options.measureEnabled` / `deliveryEnabled`, по ставке `RateCatalog` (`rates.misc.measure` / `.delivery` любого изделия).
    - минимальный заказ -- `rates.misc.minOrder` к итогу проекта.
    - `kind`: `incomplete`, если хоть одно изделие incomplete; иначе `manual`, если хоть одно manual, у кого-то работа null, или общий раскрой группы не удался (`reason: 'insufficient_stock'` и т.п. из `planMaterial`); иначе `ok`. При `manual` известные изделия всё равно получают `price`.
    - сумма `items[].price` + `measure` + `delivery` + `minOrderTopUp` == `total` (ok).

- [ ] **Step 1: Write the failing tests** (`tests/project-pricing.test.js`, состояния через `createFakeDoc` + `ConstructorState.readConstructorState`, как в `tests/company-rates.test.js`; камни -- заглушки со своими плитами)
  - `one item: the project is the item` -- `priceProject([s]).total === priceItem(s).result.total`.
  - `same stone: one cut, never dearer than apart` -- столешница 600×2400 и подоконник 300×1200 одного камня на плитах 3200×1600: `total <= сумма двух отдельных total`; `groups.length === 1`; сумма `items[].price` + доп. строки == `total`.
  - `different stones: their own slabs` -- те же изделия, разные камни: `groups.length === 2`.
  - `measure and delivery once` -- оба изделия с `opt-measure` и `opt-delivery`: `measure === 15000`, `delivery === 12000` (один раз).
  - `min order on the project` -- два маленьких изделия, каждое ниже 20 000: `minOrderTopUp` считается от суммы проекта.
  - `a manual item keeps the others priced` -- второе изделие из распроданного камня (`available: false`): `kind === 'manual'`, у первого `price` число, `total === null`.
  - `combined stock short` -- два изделия одного камня с одной плитой, каждое помещается отдельно, вместе нет: `kind === 'manual'`, `reason === 'insufficient_stock'`.
  - `surface items take the slabs left` -- пол 2000×2000 и столешница одного камня: `groups[0].nSlabs` = плиты деталей + плиты площади.

- [ ] **Step 3: Implement** `project-pricing.js`.
- [ ] **Step 4: Run** -- PASS; весь набор тестов на LF-копии -- PASS.
