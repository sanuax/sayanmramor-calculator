# Проект: несколько изделий в одном расчёте

Владелец, 2026-11-17. Пока только локально (на сайт не выкладывать).

## Зачем

Клиент считает не одно изделие, а весь свой проект: например кухонную столешницу, подоконник и
ступени. Он хочет видеть их вместе в одной 3D-сцене, облетать и рассматривать каждое, получить одну
общую цену и отправить одну заявку.

## Цели

- В калькуляторе можно собрать несколько изделий (любых из 10 типов, в любом сочетании, одного типа
  тоже несколько: две столешницы).
- Все изделия проекта стоят в одной 3D-сцене; камера подлетает к любому из них и показывает весь проект.
- Одна общая цена: изделия из одного камня раскладываются на одни плиты (общий раскрой); у разных
  изделий могут быть разные камни.
- Одна заявка и одна ссылка/паспорт на весь проект.

## Не цели

- Расстановка «как в комнате» (столешница к стене, подоконник к окну) и перетаскивание изделий руками.
- Режимы «День» / «Вечер» с мебелью для всего проекта сразу (см. «3D»).
- Изменения на сайте (sayanmramor.ru) сверх того, что нужно, чтобы заявка дошла.

## Анти-цели (провал, даже если «работает»)

- Человек, который считает одно изделие, видит что-то сложнее, чем сейчас.
- Выбор одного изделия «протекает» в другое (раковина второй столешницы появилась у первой).
- Цена проекта отличается от суммы того, что клиент видит по изделиям, без понятной причины.

## Подходы (выбран 1)

1. **Проект из снимков изделий (выбран).** Форма, как сейчас, редактирует одно, активное изделие.
   Остальные хранятся снимками выбора (тот же механизм, что у ссылки-паспорта: поля, отличные от
   начальных). Цена и 3D каждого изделия считаются чистыми модулями (ConstructorState с поддельным doc,
   GeometryModel, SceneLayout, ProductParts, Pricing) без формы.
2. Своя копия формы на каждое изделие: дублирование страницы на 5600 строк. Отклонён.
3. Отдельный расчёт каждого изделия и сумма: нет общего раскроя, а владелец выбрал его. Отклонён.

## Как это видит клиент

```
┌ шаги изделия (как сейчас) ──────────┐  ┌ 3D ─────────────────────────────┐
│                                     │  │ [Весь проект] [Столешница] [Подоконник] │
│                                     │  │      ▢▢▢      ▭        ⌸            │
│                                     │  │                                  │
│                                     │  └──────────────────────────────────┘
│                                     │   Проект: 3 изделия
│                                     │   ● Столешница · Delicato  198 000 ₽  ✎ ×
│                                     │   ○ Подоконник · Delicato   24 000 ₽  ✎ ×
│                                     │   ○ Ступени · Nero          86 000 ₽  ✎ ×
│                                     │   [+ Добавить изделие]
│                                     │   ИТОГО ≈ 308 000 ₽
└─────────────────────────────────────┘
```

- Пока изделие одно, всё как сейчас; добавляется только кнопка «+ Добавить изделие» в панели цены.
- «+ Добавить изделие»: текущее изделие сохраняется в проект, начинается новое с шага «Тип изделия».
  Камень нового изделия по умолчанию тот же, что у предыдущего; клиент меняет его на шаге «Материал».
- С двух изделий в панели появляется список проекта: изделие, камень, цена, «изменить» и «убрать».
  Активное изделие отмечено; нажатие на другое делает его активным: его выбор возвращается в форму,
  камера подлетает к нему.
- «Убрать» спрашивает подтверждение; последнее изделие убрать нельзя (проект не бывает пустым).
- Проект переживает перезагрузку страницы (хранится в браузере).

## 3D

- Изделия стоят в ряд на общем полу «как на витрине»: вдоль одной линии, задней стороной на одной
  прямой, с промежутком ~0,8 м; каждое опущено на общий пол своей нижней точкой. Порядок -- порядок
  в проекте.
- Над 3D кнопки: «Весь проект» и по одной на изделие. Камера плавно подлетает (та же пружина, что у
  видов). Облёт, приближение -- как сейчас.
- Пока клиент правит изделие, камера смотрит на него (как сейчас на единственное изделие); изменения
  размеров плавные, как сейчас.
- Режимы «День» / «Вечер» и кромка крупным планом -- для активного изделия: в этих режимах на экране
  только оно (комната и мебель строятся под одно изделие). «Студия» показывает весь проект.
- «Размеры» -- у активного изделия.

## Цена

- Каждое изделие считается, как сейчас (его работа, вырезы, кромка, швы, монтаж, полировка...).
- Камень: изделия группируются по камню. В группе все детали всех изделий раскладываются на плиты
  одним раскроем (как фартук и остров со столешницей). Изделия «площадью» (пол, стены, фасады, панно)
  того же камня берут плиты, оставшиеся после деталей.
- Замер и доставка -- один раз на проект (если клиент отметил их хотя бы у одного изделия).
  Разгрузка и расходники -- по площади, как сейчас (сумма). Минимальный заказ -- к итогу проекта.
- Если у какого-то изделия цену уточняет менеджер, итог проекта тоже «уточнит менеджер»; известные
  изделия показывают свои цены.
- Цена изделия в списке проекта = его работа + его доля камня группы (камень группы делится между
  изделиями по площади их деталей). Сумма цен изделий равна итогу проекта, кроме замера, доставки и
  доплаты до минимального заказа -- они отдельными строками итога.

## Итог, заявка, паспорт

- Шаг «Итог» показывает проект: изделия карточками (как сейчас одно), камни и плиты по группам, итог.
- «Получить расчёт» -- одна заявка на сайте: «Проект: N изделий», камни, краткий список, итог;
  ссылка «Открыть в калькуляторе» открывает весь проект.
- Ссылка проекта: тот же формат паспорта с версией 2 (pv=2) и изделиями p1, p2... (каждое -- его
  собственный паспортный запрос). Старые ссылки (pv=1) открываются как раньше, одним изделием.
- Паспорт PDF проекта: страница проекта (список, итог, QR) и страницы каждого изделия.

## Решения исполнителя

- Модуль `project-model.js` (чистый): список изделий, снимки, активное, добавление/удаление, ссылка
  проекта (pv=2), хранение в браузере.
- Модуль `project-pricing.js` (чистый): группы по камню, общий раскрой, доли камня, итог проекта.
- Сцена: SceneLayout каждого изделия со сдвигом; ThreeScene рисует несколько групп (одна на изделие),
  `focus(index)` и «Весь проект».
- Переключение изделий: форма сначала сбрасывается к начальным значениям, затем в неё
  восстанавливается снимок -- поля одного изделия не протекают в другое.
