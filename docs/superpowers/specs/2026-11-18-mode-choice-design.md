# Одно изделие или проект: выбор при открытии калькулятора

Владелец, 2026-11-18. Пока только локально (как и проект, см. 2026-11-17-project-design.md).

## Зачем

Калькулятор умеет и одно изделие (как сейчас на сайте), и проект из нескольких изделий. Это два разных
сценария: человек, который считает одну столешницу, не должен видеть проект; человек с ремонтом квартиры
сразу собирает проект. Клиент выбирает сам на первом экране.

## Как это видит клиент

- Калькулятор, открытый без ссылки на изделие, начинается с экрана на всю страницу: «Что будем считать?»
  и две большие карточки -- «Одно изделие» и «Проект». Если в браузере есть начатый проект, на карточке
  проекта -- «Продолжить проект: N изделий» и ссылка «начать новый».
- Ссылка с сайта на изделие или камень (?product=, ?stone=) и паспорт одного изделия (pv=1) открывают
  «Одно изделие» сразу, без выбора; ссылка проекта (pv=2) -- проект.
- «Одно изделие» -- как сейчас на сайте: нет «+ Добавить изделие», списка проекта, сохранённый проект не
  трогается. На «Итоге» -- «Сделать проектом» (решение владельца, вариант А): посчитанное изделие
  становится первым изделием проекта, сразу начинается второе. Если в браузере уже был начатый проект --
  сначала вопрос, заменить ли его.
- «Проект» -- всё, что сделано 2026-11-17; заголовок страницы -- «Рассчитайте стоимость проекта».
- Над выбором типа изделия -- «Сменить режим» (назад к выбору); кнопка «Назад» браузера тоже. Проект при
  этом остаётся в браузере. «Одно изделие» из выбора начинается с чистой формы.

## Решения исполнителя

- Режим -- переменная страницы `calcMode` ('single' | 'project' | null -- выбор на экране); экран --
  `#modeChoice` перед калькулятором; класс `choosing-mode` на `<body>` прячет калькулятор, заголовок и
  подзаголовок, пока выбор на экране.
- Проект хранится в браузере только в режиме «Проект».
- Выбор режима добавляет запись в историю браузера (history.pushState), «Назад» возвращает к выбору.
